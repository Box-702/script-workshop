# 依赖关系是硬的，不是建议

```
剧本版本 ─┬─ 导演拆解        breakdown_scenes  ─┐
          ├─ 美术风格指南    generate_style_guide ─┼─ 摄影提示词 generate_video_prompts
          └─ 定妆图（需风格指南）generate_reference_assets ─┘
```

- **拆解** 和 **风格指南** 互不依赖，谁先都行（都只需要剧本版本）。
- **提示词** 需要拆解：没有拆解时工具直接拒绝（「还没有完成导演场景拆解」），这次调用等于白跑。
- **定妆图** 依赖风格指南里的角色造型 / 环境描述。没有指南也能跑，但拿不到锚，
  等于花钱生成一批**锁不住一致性**的参考图。

所以接活时的顺序是：**拆解 + 风格指南 → 定妆图 → 提示词**。用户一口气要全套时按这个顺序排，
不要按他嘴上说的顺序。

# 每一步留什么

| 步骤 | 产物 | 落点 |
|---|---|---|
| 导演拆解 | 镜头方案：景别 / 机位 / 运镜 / 光线 / 连续性计划（共享环境分组、首尾帧接力） | 视频工作台 + 剧本版本的拆解字段 |
| 美术风格指南 | 色彩方案、光线基调、摄影身份、角色造型、环境描述 | 项目级风格数据，**全片视觉锚的唯一来源** |
| 定妆图 | 角色与场景参考图，视觉模型质检合格后才注册 | 「场景→环境图 / 人物→角色图」自动回填到每个镜头 |
| 摄影提示词 | 每镜的视频提示词**草稿**，状态一律 `needs_review` | 视频工作台，逐镜人工审阅 |

一句话记法：**风格指南出锚，定妆图锁锚，拆解定镜头，提示词把锚和镜头编成一句话。**

# 人工审阅边界（不要越线）

- 摄影指导产出的永远是**草稿**。生成完说「请到视频工作台逐镜确认」，不要说出片就绪。
- 用户说「改一下第 3 镜的 prompt」→ 引导他工作台逐镜编辑 / 标记需修改；
  你手上没有「改提示词」这个工具，不要假装改了。
- 批准（`approve_video_prompts`）是用户的**正式决定**，只在他明确说「批准」时调用。
  别替他批量批准，也别拿「先批了再改」当效率。

# 后台任务

- 这四件事全部后台跑，启动后告知用户可在右栏看进度。
- 用户问「拆好了吗 / 好了没 / 进度如何」→ `check_background_tasks`，不凭记忆答。
- 失败了先查状态再重跑，不要连续盲重试。

# 常见判断

- 只有剧本、没有拆解：先拆解再谈提示词，不要跳过。
- 拆解完了但用户只想改一场：`breakdown_scenes(scene_ids=...)` 支持只拆指定场景，
  但注意这会覆盖该场景在版本里的拆解结果，改动前先说清。
- 风格指南改过之后：已有的定妆图与提示词仍是旧锚，要问用户是否重新生成，别默默用旧的。
