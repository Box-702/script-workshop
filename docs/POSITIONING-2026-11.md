# 问剧定位复盘：从试用反馈看「专注做工作流」是否成立

> 2026-11-02 · 基于对 iMini、即梦（含 10-26 新上线的短剧工作室）、可灵、海螺等产品的试用与调研

---

## 一、结论先行

你的判断**方向正确，但需要修正一处**：

1. ✅ **「小说→提示词」的前半段，单独拿出来确实不是壁垒**——iMini 把它做成了一个薄 Skill，即梦把它做成了产品入口。纯"改编智能"会被任何平台封装。
2. ⚠️ **但"专注做工作流"不等于"做薄 Skill 的同类"**——2026-10-26 即梦上线「短剧工作室」，已经把小说→剧本→资产→分镜→成片**整条链**做进平台（¥69/月 + 视频按秒计费）。在功能覆盖上我们已经没有任何翻身机会。
3. 🎯 **真实的机会在平台结构性做不到的地方**：本地私有（版权/备案敏感）、无积分锁定、中间产物完全可编辑、**开放对接任意视频引擎**（即梦 CLI / 可灵 API / 海螺 API / 内置 MiniMax）、创作资产沉淀在作者自己手里。
4. 📌 **产品重心应从"对话式 Agent"转向"工作流引擎"**：集-镜结构、改编进度、审阅卡片、角色资产库升为主界面；对话降为辅助交互；视频生成降级为可插拔后端之一。这和你之前提的「按集划分 + 进度百分比」本来就是同一件事。

---

## 二、竞品拆解

### 2.1 iMini —— 通用 Agent 平台，前半段是薄 Skill

- 定位：聚合 25+ 模型的"超级智能体"（GPT-5/Claude/Veo/Sora/可灵/海螺……），对话式交付
- 「小说转短视频」流程实测：上传 txt → 追问形式（3分钟分镜 or 15秒短片）→ 确认扣 3000 credits → 出一段 15s
- 收费：$10/66 每月（Pro/Ultra），积分制
- **对前半段的投入深度**：一次 LLM 拆解，无角色资产、无跨镜一致性、无集-镜结构、中间产物不可编辑
- 启示：它证明了"小说改编"可以被封装为 Skill；也证明了薄封装的产出质量上限很低

### 2.2 即梦「短剧工作室」—— 10 月 26 日上线，最需要正视的对手

字节把编剧、选角、分镜、后期全塞进了一个项目容器：

| 能力 | 内容 |
|---|---|
| DreamScript 剧本模型 | 10 万字小说→最多 100 集剧本；「剧本医生」检查前三集钩子；台词对照人设体检 |
| 资产库 | 角色/场景/服装/道具/音色自动建档，跨集"同一张脸"，改一处全局同步 |
| DreamShot 分镜 | 自动拆镜，批量修改，运镜库 |
| 3D 导演台 + 白模 | 生成前先摆机位、走位、预演，一场 1 分钟的戏用 8 秒成本预览——**降废片率** |
| 重制转绘 | 上传成片→换画风/出海本地化（18 地区），单项目 250 分钟 |
| 团队版 | 多人资产共享、统一积分 |

- 价格：会员 ¥69/月起；Seedance 2.5 720P 约 **¥0.19/秒**（团队 ¥0.177）
- 启示：**功能覆盖维度上我们已出局**。它甚至做了白模预演——我们上周做的"白模自导入"它也有产品化对应物。

### 2.3 可灵 / 海螺 —— 生成引擎，明确不做前半段

- 第三方横评（2026-09）：两者在"剧本解析/小说拆解"和"剧集合成"上均为 1/5 分——**生成引擎刻意把前半段留白**
- 可灵强在单镜运动质量；海螺强在对白口型 + 多参考图一致性
- 启示：上游（结构化分镜包）与下游（视频引擎）之间**天然存在接口层**，这是生态位

### 2.4 行业里的真实工作流（创作者实践）

公开测评里反复出现的组合：
**扣子（项目管理/分镜提示词标准化）→ 即梦（出图）→ 可灵（图生视频）→ 剪映（后期）**
——创作者自己在手工拼"工作流管理 + 多引擎生成"。**没有工具把这件事产品化好**，即梦只服务自家生态，扣子是通用平台不是短剧专用。

## 三、行业大盘（2026，DataEye / QuestMobile 等口径）

- AI 剧漫剧市场规模预计 **400 亿元**（+138%）；前 8 个月上线短剧 43 万部，AI 剧占九成
- 但**爆款率 0.16%~0.47%**，万播收益从 30-100 元跌到 5-10 元，98.7% 项目半年不回本
- 投流占收入 60-80%；单集算力成本从 17 元涨到 80-100 元，精品 800-1500 元/分钟
- 监管：4 月起"先备案后上线"，9 月起 AI 微短剧强制标识
- 分账转向：红果取消普惠保底；**"人机融合"内容最高可分 95%**（纯 AI 流水线被系统性压低）

**解读**：行业从"谁能生成"转向"谁能持续做出可回本的内容"。价值重心从生成算力移向**内容质量控制与生产管理**——这正是工作流工具的地盘。

## 四、对问剧现状的判定

### 已被证伪的假设
- ❌ "对话式 Agent 是主交互" —— iMini/即梦都证明：生成类任务用户要的是**可控的工作台**，对话适合启动和微调，不适合承载 100 个镜头的管理
- ❌ "内置视频生成是核心卖点" —— 烧算力、拼不过平台补贴价（¥0.19/秒）
- ❌ "全链路功能覆盖" —— 即梦短剧工作室已全面覆盖

### 仍然成立的资产（我们的真实家底）
- ✅ **数据模型**：projects / versions / characters / locations / shots / assets——薄 Skill 做不了这个，这是"工作流引擎"的骨架
- ✅ **审阅卡片模式**：中间产物全部可见、可改、可局部重生成——纯对话平台做不到
- ✅ **本地化 + 全存 SQLite**：版权敏感、备案留痕、数据归作者——云端平台结构性给不了
- ✅ **多模型配置**：对话/生图/视频模型已全部用户可选——天然适配"开放对接"路线

## 五、定位建议

### 推荐定位：**「小说→短剧的前期生产管线 + 开放导出」**

一句话：**即梦们的好上游，不当前半段的薄 Skill。**

```
问剧（本地）                          生成/发布（用户自选）
┌─────────────────────────┐          ┌──────────────────┐
│ 小说导入 → 剧本 → 分集    │          │ 内置 MiniMax（可选）│
│ → 角色/场景资产库（圣经） │  ──导出──▶│ 即梦 CLI / 剪映    │
│ → 集镜分镜表 + 提示词包   │          │ 可灵 API / 海螺 API │
│ → 审阅/局部重写/进度管理  │          │ 备案素材包          │
└─────────────────────────┘          └──────────────────┘
```

### 三个方向对比

| 维度 | A. 纯前期工作流（推荐） | B. 全链路但工作流为主 | C. 维持现状 |
|---|---|---|---|
| 竞争 | 与即梦错位，生态位空白 | 与即梦正面碰撞 | 被薄 Skill 边缘化 |
| 成本 | 不烧视频算力 | 烧，且拼不过 ¥0.19/秒 | 烧 |
| 用户 | 专业创作者/工作室/版权敏感团队 | 泛用户 | — |
| 现有代码复用 | ~85%（管线全保留，改 UI 重心 + 导出） | ~80% | — |
| 风险 | 即梦继续向上游吞噬（剧本医生已很深） | 全线作战 | 慢性死亡 |

### 若走路线 A，改造清单（按优先级）

1. **P0 · 集-镜结构**：项目内按集划分（Episode → Shot 两级），改编进度百分比——本来就是你提过的未完成需求，现在是定位的骨架
2. **P0 · 提示词包导出**：每镜导出「首帧图提示词 + 运镜/动作提示词 + 角色一致性约束」结构化包（Markdown/JSON/剪映草稿格式），兼容即梦/可灵/海螺的输入习惯
3. **P1 · 角色圣经强化**：角色资产库升级为可跨项目复用的"演员库"（我们已有白模上传，补上多形象/多集数标注）
4. **P1 · UI 重心迁移**：从"对话主界面"改为"工作台主界面"（分集进度看板 + 分镜表），对话收进侧栏
5. **P2 · 对接引擎**：内置 MiniMax 保留；打通即梦 CLI / 可灵 API 作为"生成执行器"，提示词包一键送出
6. **P2 · 备案素材包**：改编溯源记录（小说→每镜的对应关系），服务备案与版权证明

### 必须诚实面对的风险

- **即梦的剧本医生/资产库已经很深**，且迭代速度是字节级。纯功能永远追不上，只能靠"私有 + 开放 + 可编辑深度"三条平台结构性做不到的腿站着
- 市场虽大（400 亿），但创作工具的付费意愿集中在头部专业团队——工具要按"专业生产力"标准做，不能按"玩具"标准
- 备案新规是双刃剑：提高门槛（利好专业工具），但也可能催生平台内置合规方案
